Encuentra el error. Entiende la causa.

Una guía breve para usar el depurador de Visual Studio Code, observar lo que ocurre durante la ejecución y corregir problemas con pruebas, no con suposiciones.

La idea esencial

Depurar no es añadir mensajes al azar: es detener el programa en un punto concreto, observar su estado y relacionarlo con el código que lo provoca.

Seis ideas que conviene dominar

Elige una sección, prueba la demostración y vuelve al código con una hipótesis concreta.

01 · CONCEPTO

El depurador hace visible la ejecución

Permite pausar un programa e inspeccionar variables, funciones, excepciones y la pila de llamadas. Por eso aporta contexto que un console.log() aislado no siempre muestra.

02 · INICIO

F5 inicia una sesión controlada

VS Code puede ejecutar el programa con una configuración automática o mediante .vscode/launch.json. launch inicia el proceso; attach se conecta a uno que ya está funcionando.

03 · PAUSA

Un breakpoint elige el momento

Coloca un punto de interrupción en la línea que quieres observar. Si ocurre muchas veces, usa un breakpoint condicional, un contador de impactos o un logpoint.

04 · CONTROL

Avanza con intención

F10 ejecuta la línea sin entrar en la función; F11 entra; Shift + F11 sale. F5 continúa hasta la siguiente pausa.

05 · EVIDENCIA

Observa el estado, no solo el síntoma

Variables muestra los valores actuales, Watch evalúa expresiones, Call Stack explica cómo has llegado hasta allí y Debug Console permite probar cálculos en ese contexto.

06 · MÉTODO

Una hipótesis se verifica paso a paso

Reproduce el fallo, formula una causa posible, coloca el breakpoint, inspecciona, corrige y vuelve a ejecutar. La última prueba debe confirmar que el error desapareció.

Demostración: localizar un índice imposible

Simula el caso de una media que recorre un elemento más de lo que existe. Pulsa los controles como si usaras F10 en VS Code.

La pregunta correcta

El resultado no es el esperado. ¿En qué vuelta del bucle deja de ser válido el estado?

  1. El breakpoint detiene la línea sospechosa.
  2. F10 aumenta i sin saltar a otra función.
  3. Variables revela que i = 4, pero solo hay índices del 0 al 3.

Código observado

const notas = [7, 8, 6, 9];let suma = 0;for (let i = 0; i <= notas.length; i++) {  suma += notas[i];}
Breakpoint activo i = 0 · notas[i] = 7 · suma = 0

Corrección: cambia i <= notas.length por i < notas.length. El último índice válido es 3.

Un flujo que se puede repetir

La depuración es una investigación pequeña: cada paso debe producir una observación útil.

Glosario rápido

Las palabras que aparecen constantemente cuando investigas un programa detenido.

Breakpoint
Punto donde el depurador pausa la ejecución.
Debug Console
Consola que evalúa expresiones dentro del contexto pausado.
Watch
Lista de expresiones cuyo valor se observa mientras avanzas.
Call Stack
Cadena de funciones activas que llevó al punto actual.
Step Over
Ejecutar la línea actual sin entrar en la función llamada.
Debug Adapter Protocol
Protocolo que conecta VS Code con el motor de depuración.
